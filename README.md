# WlanShare · 局域网文件与协作工具

PC（Windows）与 Android 双端客户端。同一局域网内**安装即被发现**，无需服务器、无需账号、无需配置。
支持文件直连传输（**断点续传**）、Markdown 文档**多人同时编辑自动合并**、消息互发、好友管理、昵称修改。

---

## 1. 交付物

| PC 客户端      | `pc/dist/WlanShare/WlanShare.exe`  | 绿色免安装，双击运行；已内置 Java 运行时，目标机无需装 JDK |

## 2. 快速开始

**电脑**：双击 `pc/dist/WlanShare/WlanShare.exe`。
首次运行 Windows 会弹防火墙提示，**必须选「允许访问」**（专用网络），否则其他设备发现不了你。

**手机**：安装 `android/dist/WlanShare.apk` → 打开 → 允许通知。

两端连同一个 WiFi / 路由器后，约 3 秒内互相出现在「附近设备」中：

1. 点「加好友」（默认对方会自动同意）；
2. 点「发消息」聊天，或「传文件」发送文件；
3. 「文档」页新建一份 Markdown，点「共享」发给好友，双方即可同时编辑。

## 3. 功能说明

### 3.1 自动发现

- UDP **组播 239.255.42.99 + 广播 255.255.255.255** 双通道，每 3 秒通告一次，端口 `45789–45794`（占用则自动顺延，支持同机多开）。
- 收到通告后立即建立 TCP 长连接，所以「发现」与「可通信」是同一时刻。
- 有活跃连接时，即使广播被路由器拦截，设备也不会被判离线。

### 3.2 文件传输与断点续传

- 32 KB 分块传输，进度实时显示；接收方可自动接收（默认）或逐个确认。
- **断点续传机制**：
  1. 发送前对文件计算指纹 `key = 大小 + 头 64KB CRC32 + 尾 64KB CRC32`；
  2. 接收方用 `key` 定位 `<数据目录>/parts/<key>.part`，把已有字节数作为 `offset` 回给发送方；
  3. 发送方从 `offset` 处 `seek` 继续发送，接收方以 `rw` 模式追加写入；
  4. 传完校验长度后把 `.part` 重命名为正式文件，临时分片自动清理。
- 传输中断（拔网线、关客户端、切后台被杀）后，**重新发送同一个文件**即从断点继续；文件页里失败的记录点一下就是「重试续传」。
- **传输记录可管理**：单条记录右键 →「打开文件 / 打开所在文件夹 / 再次发送（选接收人）/ 删除这条记录」；
  卡片右上「清空记录」一次清掉所有**已结束**的记录（传输中的保留、硬盘上的文件不删）。
  「打开所在文件夹」在 Windows 上会直接在资源管理器里选中该文件，方便立刻再发一次。
- 指纹包含头尾内容，所以「大小相同但内容改了」的文件不会被误当成同一个断点。
- **「发送给」显示名遵循统一规则**：本机备注名 &gt; 对方昵称 &gt; 设备名称。
  给设备改过备注就显示备注，没设昵称的设备直接显示机器名（如 `ThinkCentre M720q`）；
  传输记录里的「发送给 / 来自」也使用同一个名字，PC 与 Android 表现一致。

### 3.3 Markdown 协作

- 文档以 JSON 保存在本机，`ver` 单调递增，每次本地修改广播 `doc.update{baseVer, ver, text}`。
- 收到远端修改时：若 `baseVer == 本地 ver` 直接采纳；否则用 **diff3 三方行级合并**（`DocMerge`）：
  - 两人改不同段落 → 自动合并；
  - 同一位置双方各自追加 → 两段都保留，且按作者 ID 排序，保证两端结果完全一致；
  - 同一段被双方改成不同内容 → 写入 `<<<<<<<` 冲突标记，等人工处理。
- **删除文档**：删除只影响本机（其它设备上的副本仍在），本机会立刻从列表移除并删掉 `docs/<did>.json`；
  同时写入一个删除标记 `docs/.deleted/<did>.gone`，用来挡住「同机多开的另一个实例保存」「重启后重新加载」
  以及「远端 `doc.sync` 回推」把这份文档又写回来。标记 7 天后自动失效，之后可以再次接收同一份共享。
- 合并结果会以 `doc.sync` 回推给其他协作者（带 `hops` 限制，避免来回震荡）。
- **协作光标行标记**：每个人在文档里的光标所在行会实时同步（300ms 节流，15 秒无更新自动清除）：
  - PC：编辑区**行首一条彩色竖条** + 编辑区右侧一个**名字小标签**（如「工作站A」），顶部还有「● 某某 正在编辑」；
  - Android：整行淡色背景（每人一色）+ 底部状态栏「● 小美 第 3 行」；
  - 颜色由设备 ID 派生（6 色调色板，两端一致），同一人两端颜色相同；断开连接时标记立即移除。
  - 打开文档时会先广播一次自己的位置，对方无需等待你移动鼠标就能看到。
  - 不需要先加好友：只要在同一局域网且对方打开着这份文档，就能看到彼此的编辑位置。
- **预览版式**：预览区按现代阅读器排版——浅灰画布上放一张白色「纸张」，左右留白充足；
  一级标题下方细分割线，二级/三级标题层级分明；引用是浅蓝卡片 + 左侧竖条；代码块是深色卡片 + 语言标签；
  分隔线为 1px 细线；支持任务列表（`- [ ]` / `- [x]`）与合并冲突高亮块。
- **表格**：不用传统网格线——1px 浅色外框 + 表头浅底加粗 + 表头下分割线 + 行间细线 + 交替浅纹，没有竖线；
  列对齐由分隔行控制：`| --- | :---: | ---: |` 分别是左 / 居中 / 右（数字列建议右对齐）。
- **HTML 块**：文档里可以直接写 HTML，预览按原样排版（不再显示成一坨代码）：
  - 围栏写法：<code>```html</code> 包住一段 HTML，适合多行、带缩进的片段；
  - 裸写法：以 `<div>`/`<table>`/`<p>` 等块级标签开头的段落会被整体识别，写单行卡片最省事；
  - 工具栏 `</>` 一键插入带样式的 HTML 卡片模板；
  - 安全过滤：`<script>`、`<iframe>`、`<embed>`、`on*` 事件属性与 `javascript:` 会被移除（两端一致）。
- **内置 Markdown 快捷工具栏**（纯 Swing 自绘，无第三方依赖）：
  - 撤销 / 重做、标题、加粗、斜体、删除线、行内代码、无序 / 有序列表、引用、链接、表格、代码块、HTML 块、分割线；
  - **插入表格可选行列**：点 `▦` 弹出 10×10 网格，鼠标划到第 N 行 M 列即高亮并显示「插入 N 行 × M 列」，
    点一下插入对应大小的表格（行数含表头，超出上限自动收敛到 10）；标题栏实时显示当前尺寸，`Esc` 或点空白关闭；
  - `Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+K` 链接、`Ctrl+Q` 引用、`Ctrl+1/2/3` 标题、`Ctrl+Z / Ctrl+Y` 撤销重做；
  - 有选区时包裹选区，没选区时插入占位文字并选中，直接改写即可；列表 / 引用 / 标题再点一次即取消；
  - 分栏模式下工具栏可横向滚动（鼠标滚轮），右侧「更多」菜单始终可以找到全部命令。
  - Android 版本是同一套逻辑，工具栏可手指横滑。

### 3.4 备注名（本机重命名对方）

- 你可以给任何设备起一个**只在本机生效**的备注名，对方不会收到通知，也不会改变他自己的昵称。
- 入口：消息页顶部「备注」按钮 / 会话列表右键「重命名备注」/ 附近设备卡片右键 / Android 长按会话或点顶部昵称。
- 备注名优先于对方昵称显示；留空即恢复原名；保存在 `aliases.json`，重启不丢。
- 搜索设备时也会匹配备注名。
- 备注名会同步出现在所有需要「这是谁」的位置：会话列表、聊天气泡、附近设备卡片、**文件页的「发送给」下拉与传输记录**、
  **文档页的「共享给」菜单、协作者标签，以及文档列表的「协作中」标记**。

### 3.5 消息：撤回 / 引用 / 语音
- **60 秒内可撤回**：长按（PC 也可右键）自己的消息 → 「撤回（N s）」，倒计时随剩余时间变化；
  超过 60 秒菜单项置灰。撤回后双方都显示「你/对方撤回了一条消息」，本机会话记录同步重写。
- **引用**：长按（PC 上也可直接**点鼠标右键**）任意消息选「引用这条消息」，输入框上方出现引用条
  （可点 × 或按 Esc 取消）。发出的气泡里，**引用块位于正文下方**（像微信的历史消息引用）：
  浅灰圆角底 + 左侧竖条 + 作者名 + 原文摘要（单行省略），自己的蓝色气泡里是半透明白色块；
  语音消息也能被引用（显示 `[语音] 7"`）。
- **PC 右键菜单**：在消息正文、语音条上右键（或按住左键 0.55 秒）都会弹出菜单——
  引用这条消息 / 复制文字 / 播放语音 / 撤回（N s）。菜单对气泡内所有子控件都生效。
- **未读红圈**：左侧导航「消息」显示未读总数，会话列表里每个会话显示自己的未读条数；
  打开该会话（或切到消息页）即清零，红圈随之消失。超过 99 显示 `99+`。
- **新消息提醒**：
  - 提示音：内置 `sounds/msg.wav`（两声短促「滴」），异步播放，不打扰当前正在看的会话；
  - 任务栏：窗口不在前台时会把窗口提到前面（Windows 会闪烁任务栏按钮），标题同时闪几下，
    并在标题上显示「· N 条未读」；没有音频设备时自动静默降级。
- **文件发送不需要加好友**：「发送给」下拉直接列出**所有在线设备**，对方在线即可发送。
- **接收文件需要确认**：默认不自动接收。对方发来文件时：
  - 有提示音与任务栏提醒，「文件」导航出现红圈（数量 = 待接收文件数）；
  - 文件页第一张卡片就是待接收文件（自动滚动并高亮描边），卡片上有「接收」「拒绝」按钮；
  - 点「接收」可选「保存到下载目录」或「另存为…」指定目录，接收完成后文件名冲突自动改名；
  - 点「拒绝」对方立刻收到「对方已拒绝」。
  - Android 端同样有接收 / 拒绝按钮，接收后保存到系统「下载」目录。
- **语音消息**：输入框左侧是一个**话筒图标按钮**（无文字），点一下开始录音，按钮变为红色停止图标并显示
  `0:03` 计时，再点一次发送、PC 旁边「取消」丢弃；Android 同样是点一下开始、再点一下发送。
  录音为 16kHz/16bit/单声道 WAV，随消息一起点对点发送（≤2 分钟），对方点气泡即可播放，播放中图标变为暂停条。
- **消息 id 全局唯一**，引用 / 撤回都按 id 定位，跨端一致。
- **输入框**：`Enter` 发送、`Shift+Enter` 换行；1～8 行自动长高（超过 8 行内部滚动），引用条出现时不会挤压输入文字；
  右上角放大图标点开**半屏编辑窗**（同样的快捷键，`Esc` 收起，文本与主输入框互通，窗口可拖动）。
- **会话列表**：右键单条会话可「重命名备注 / 清空聊天记录 / 删除会话」——
  清空只删本机聊天记录；删除会一并清掉记录、备注与好友关系并把该条目从列表移除（对方再发消息时会重新出现），
  适合清理改名后残留的旧条目。会话头像与名字统一跟随备注名。
- **会话搜索**：列表标题右侧放大镜图标，输入关键词同时搜索「设备 / 好友昵称」与「历史聊天记录」，
  结果分两段列出并显示时间与命中片段；点消息结果会跳转到该会话并**滚动到那条消息**（琥珀色描边高亮 2 秒）。

### 3.6 界面布局

- **选中配色完全自绘**：部分 Windows / Metal 主题会用选区背景色盖住选中文字（尤其从行首开始选时），
  表现为「选中后颜色自动去掉、看不见字」。现在文档编辑器的选区由程序自己绘制（淡蓝底 + 深蓝字），
  其它输入框统一为同一套配色，不再受系统主题影响。
  绘制按**视觉行**（自动换行后的每一行）进行，长行选中也不会错行、文字重叠。
- **全局侧边栏可折叠**：点左上角品牌行右侧的 `‹`，侧栏收成 74px 图标条（导航图标保留、悬停有提示），
  底部出现 `›` 可展开；折叠后整个内容区变宽。
- **文档页 / 消息页左侧列表也可折叠**：点列表标题右侧的 `‹` 收起，正文区立即铺满；收起后头部出现 `›` 可随时展开。
- 两层折叠互相独立，可任意组合。
- **文档支持三种视图**：右下角「编辑 / 分栏 / 预览」——
  - 编辑：编辑器独占整个宽度，适合长时间写作；
  - 分栏：左编辑右预览（默认）；
  - 预览：只显示渲染结果，适合阅读与演示。
- 折叠列表与视图模式互不干扰，折叠后编辑器同样铺满。

### 3.7 消息 / 好友 / 改名

- 消息点对点直连，离线时进入发送队列，重连后自动补发；聊天记录按会话落盘。
- 好友申请默认自动同意（可在设置关闭），好友列表随昵称变化实时更新。
- 改昵称后立即通过 TCP 通知在线设备，并通过下一次广播扩散。

## 4. 协议与端口

```
帧格式：[int32 total][int32 headerLen][JSON header (UTF-8)][payload]
```

| 消息                                                                      | 方向 | 用途                                    |
| ------------------------------------------------------------------------- | ---- | --------------------------------------- |
| `hello`                                                                   | 双向 | 身份交换（id / 昵称 / 设备 / TCP 端口） |
| `friend.req` `friend.ack` `friend.del`                                    | 双向 | 好友关系                                |
| `chat`                                                                    | 双向 | 文本消息                                |
| `file.offer` `file.accept{offset}` `file.chunk` `file.done` `file.reject` | 双向 | 文件传输 / 断点续传                     |
| `doc.create` `doc.update` `doc.sync` `doc.request` `doc.aware`            | 双向 | 文档协作                                |
| `nick` / `ping`                                                           | 双向 | 改名 / 心跳                             |

端口：发现 `UDP 45789+`，传输 `TCP 随机端口`（在 `hello` 中告知对方）。

## 5. 数据存放

| 平台    | 位置                                                                                                 |
| ------- | ---------------------------------------------------------------------------------------------------- |
| Windows | `%APPDATA%\WlanShare\`（config.json / friends.json / aliases.json / docs/ / chat/ / recv/ / parts/） |
| Android | `/Android/data/com.wlanshare.app/files/share/`（同上结构）                                           |

Android 收到的文件可在「文件」页点击记录**导出到系统下载目录**（Android 10+ 无需权限）。

## 6. 常见问题

**搜不到对方？**

1. 确认在同一路由器 / 同一网段（手机别开流量，关掉「智能网络切换」）；
2. Windows 防火墙必须放行（控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 勾选 WlanShare 专用网络）；
3. 路由器若开了「AP 隔离 / 客户端隔离」，设备之间互相不可见，需要关掉；
4. 公司/酒店 WiFi 常隔离终端，可改用手机热点让电脑连上。

**设置页「广播收包」一直是 0？** 说明本机根本收不到广播（防火墙或网络隔离），此时只能排查网络。

**传输中断了怎么办？** 在「文件」页点那条失败的记录即可重试，进度会从断点继续，不会重传已完成部分。

## 7. 构建与测试

```bash
# 一键构建（PC + APK）
python build/build_all.py

# 先跑 28 项协议自测，再构建
python build/build_all.py --test
```

依赖：JDK 17+（`JAVA_HOME`）、Android SDK build-tools 36、Python 3。
PC 端用 `jpackage` 打包成 app-image；APK 用 `aapt2 → javac → d8 → zipalign → apksigner` 全命令行构建。

> 仓库内**不含** `pc/env`（打包用的 JRE 运行镜像，约 40MB）、`pc/dist`、`android/dist` 与 `temp/`，它们由本机构建产生。
> 首次打包前需要把 JDK 运行镜像放到 `pc/env`（`jlink` 或复制现有 JRE 均可）；只想跑源码版的话，
> 直接 `javac` 到 `build/pc` 后 `java -cp build/pc com.wlanshare.Main` 即可，不需要 `pc/env`。
